Lantern, by Elves

From the team that brought you Elves. Herdr manages the herd. The herd is in the field. Lantern illuminates the field. You talk; it runs herdr. Each person picks their own helper CLI and model. Public walkthrough: aigorahub.github.io/herdr-lantern.

Install the plugin

  1. Need Herdr 0.7.5+ and Python 3 on macOS, Linux, or Windows, already running and attached. Windows also needs Git for Windows. Lantern accepts python3, python, or py -3.
  2. If you previously linked a local checkout, unlink it first: 
    herdr plugin unlink aigora.lantern
  3. Then install and open: 
    herdr plugin install aigorahub/herdr-lantern && herdr plugin action invoke aigora.lantern.open

The first lantern chat asks for a spawn default (harness, model, setting). After that, naming a repo is enough. Developers can herdr plugin link /path/to/herdr-lantern instead. Do not link and GitHub-install the same id at once.

Pick your helper CLI

The lantern is not a new chat UI. It launches one of the CLIs you already have. That choice is yours; it is not a shared team model.

HelperWhat to installYour helper.conf
Cursor Cursor CLI as agent (Ultra / Composer) HELPER_AGENT="agent". HELPER_MODEL="cursor-grok-4.6-high-fast". HELPER_PERMISSION smart uses --auto-review.
Devin Devin CLI on PATH (often ~/.local/bin/devin) HELPER_AGENT="devin". Leave HELPER_MODEL empty. Set HELPER_PERMISSION to smart.
Claude Claude Code as claude HELPER_AGENT="claude". Optional HELPER_MODEL and HELPER_EFFORT.
Codex Codex CLI as codex HELPER_AGENT="codex". Optional model and effort.
Grok Grok CLI as grok (often ~/.grok/bin) HELPER_AGENT="grok". Optional model and effort.
Pi Pi CLI on PATH as pi (typically ~/.local/bin/pi) HELPER_AGENT="pi". Optional HELPER_PROVIDER (--provider), HELPER_MODEL (--model; supports provider/id), and HELPER_EFFORT (--thinking).

The spawn default is separate from the lantern chat CLI: HELPER_SPAWN_KIND, HELPER_SPAWN_MODEL, and HELPER_SPAWN_EFFORT are what Lantern opens when someone just names a repo.

Claude, Grok, and Cursor seats start in the smart-auto permission tier. Codex seats pass --dangerously-bypass-approvals-and-sandbox so they do not stop for command or sandbox confirms. The herdr wrapper puts that flag immediately after --, including when the seat omitted it or placed it after resume or review. bypassPermissions, --yolo, --force, and --always-approve stay off unless a user asks for yolo and confirms the exact flag and lost protections. Pi has no permission modes: HELPER_PERMISSION is accepted and ignored for Pi, and Lantern never passes any approval-bypass flag to it. Before seating, Lantern checks the live model catalog and availability. After a seat, it renames the tab to <slug> · <kind> and reports the kind, model, effort, Fast state, and task.

Edit your config

$EDITOR "$(herdr plugin config-dir aigora.lantern)/helper.conf"
HELPER_AGENT="agent"
HELPER_MODEL="cursor-grok-4.6-high-fast"
HELPER_PROVIDER=""
HELPER_EFFORT=""
HELPER_CWD="~"
HELPER_SPAWN_KIND="claude"
HELPER_SPAWN_MODEL=""
HELPER_SPAWN_EFFORT=""
HELPER_PERMISSION="smart"
HELPER_EXTRA_ARGS=""

Empty HELPER_AGENT picks the first of agent / Devin / Claude / Codex / Grok / Pi on PATH. Cursor with an empty model defaults to Grok 4.6 High Fast. Leave Devin’s model blank.

Open it

  1. Once it is installed, in Herdr: press ctrl+b, then capital H. Lowercase h still moves focus left. If the binding is missing, map prefix+H to aigora.lantern.open in your config.toml, then herdr server reload-config.
  2. Or from any terminal, after putting this repo’s hsh on PATH: 
    hsh

Close the chat by quitting the helper CLI. Escape stays inside the CLI. For Cursor agent: ctrl+c (twice if a turn is running), or ctrl+d on an empty prompt. Script and config edits do not need a Herdr restart — reopen the lantern.

Quit the chat before you upgrade, relink, or reinstall the plugin. herdr plugin install and herdr plugin link drop Herdr’s record of a running lantern pane, so that tab stops answering to herdr plugin pane focus and the next open seats a fresh chat beside it. Close the leftover tab with herdr pane close <pane_id>.

The lantern checks for a newer published version at light-up and offers the update — it asks first, never upgrades silently. There is no herdr plugin update; a GitHub install refreshes by running the install command again. A linked checkout is only told it is behind; pull it yourself.

Where it sits

  1. The first open creates a workspace labelled 🔥 lantern at your home directory and seats the chat there as a tab named home — suffixed with what the chat runs, e.g. home · claude · opus, and the chat's first line names the same. It is not dropped into the workspace you happen to be in, and the empty shell tab of the new workspace is closed, so the chat sits alone. The lantern in the sidebar is how you spot it.
  2. Every later open reuses it. A chat that is still running is focused wherever it sits, so moving or renaming that tab is safe. If it has exited, a new chat is seated in the same workspace. Lantern does not open a second lantern workspace.
  3. The new workspace lands last in the sidebar. There is no pin-to-top; drag it where you want it.

The chat runs in the plugin state workdir. Home is only where the workspace sits and the search root the helper is told about (HELPER_CWD). Your repositories keep their own workspaces. When the helper CLI exits, the tab closes, and the lantern workspace closes with it if that chat was the only tab. Herdr reuses workspace and pane ids after a restart, so Lantern checks the remembered ids before it trusts them: keep the 🔥 lantern label if you want that workspace reused after the chat closes.

Run a herd with Elves

Name the repos, run, and model. Lantern reuses one workspace per checkout and keeps one live Elves driver per run. The driver owns changes, reviews, fixes, and authorized merges. Lantern monitors each run.

  • sweep battle-paddle and image-maker with astra highOne audit agent per repo. Report high value issues, then stop. No Elves run starts until you name it.
  • issue harvest battle-paddleRead open issues and group them into 1-3 landable runs. Lantern brings the menu. You pick.
  • stage relay recovery on battle-paddle with fable highPrepare a plan PR if needed, an implementation draft, a worktree, and session records. Bind prewalk, execution, and independent review to the named routes. Stop when ready to start.
  • landable loop relay recovery on battle-paddle with astra high, merge when cleanAudit, stage, execute, review, fix, and review again. The driver updates docs, changelog, and version, then merges, publishes the GitHub version, checks deployment, and pulls main.
  • parallel pack relay recovery on battle-paddle and export fixes on image-maker with astra high, merge when cleanStart independent runs across repos. Keep healthy runs moving. Interrupt you only for NEEDS YOU: a real question, exhausted quota, or a review with unresolved findings.
  • cutoff resume relay recoveryResume the exact session, kind, model, effort, worktree, and phase. A login picker gets one restart with no keypress. Competing drivers stay stopped.
  • close barList only tabs with merged work and current main. Each needs a passed deploy check or a stated deployment block. You name what to close. Lantern keeps its home tab open.

Omit merge when clean to stop at a landable PR unless you already gave merge authority for that run. A sweep, harvest, or stage does not grant merge authority. Lantern never merges, edits product repos, or prompts a working chat.

Lantern can grant routine permissions within the named run scope. It reads the blocked prompt, selects a visible allow once option, and checks progress. It does not grant access outside the run scope or turn on broad bypass settings. Yolo stays off unless you name it.

Herd runs need the installed Elves skill. The driver controls parallel batches within its repo. The herd rules load on every Lantern launch, including with a saved custom prompt. Reopen Lantern after an upgrade.

Agy reviews always use /boost in plan mode, including reviews of fixes. Prefer the listed gemini-3.8-flash-high model. Keep a separate session from the code writers. If Boost fails or cannot be confirmed active, use an approved independent fallback or report a block. A plain Agy response does not satisfy review. Use a supervised terminal when headless transport is unqualified. Pass the absolute review workspace to every Boost worker. Approve only scoped review actions. Keep the terminal open until the children finish and the final report names the exact commit. A parent success or delegation notice does not prove completion. Keep /grill-me for optional planning interviews.

Choose a live model

  • astra, gpt-6 astra, and astra high select Codex gpt-6-astra. The default effort is medium. Supported efforts are low, medium, high, xhigh, max, and ultra. Bare gpt-6 needs a model choice.
  • fable, fable 5.1 high, and claude-fable-5-1 high select Claude Code Fable 5.1. Routing reads the live initialization response and pins claude-fable-5-1. Supported efforts are low, medium, high, xhigh, and max. Old CLI help examples do not limit the model list.
  • An explicit Cursor request uses its own live model list. Fable 5.1 IDs are listed. No Cursor Astra ID was listed in the 2026-09-05 check.

Codex Fast is off by default. An explicit Fast request needs a listed Fast tier. Codex seats keep --dangerously-bypass-approvals-and-sandbox, including on resume. A model check does not prove that a review ran. Review launch checks also cover local files, sockets, login, and sandbox access. A named review kind cannot change without your choice.

What to say

  • “Who is working, blocked, or done?” Inspect-only. It reads herdr agent list and says who needs you.
  • “What are they working toward?” Titles, Claude /goal / recap lines, and who is waiting on a merge. Status alone is not progress.
  • “Jump me to the love-spark agent.” Reuse the existing workspace. Unnamed agents use a pane id, e.g. w1X:p1.
  • “Open the image maker repo with claude.” Reuse the workspace and agent if they are already there. Agent slugs: image-maker, not “Image Maker”.
  • “There is a PR on battle-paddle. Get a Codex review.” Resolve the repository and PR first. Check the model before any workspace or tab change. Lantern does not edit the repository.
  • “Open battle paddle with Grok.” Bare Grok means Cursor with a live Cursor Grok model. Say Grok Build to use the Grok CLI.
  • “Create a GitHub repo for X.” Always gh repo create --private. Public only when you ask for public.
  • “Make a worktree on herdr for branch helper-tests.” herdr worktree create, not a second workspace on the main checkout.
  • “How’s the night shift?” Optional. If Elves session files are around, it reads the floor. No Elves install required for the rest of Lantern.

Create / start / focus / close go through the helper, which reruns them with HERDR_HELPER_OK=1. Ask for something and the lantern does it, then tells you what it did. It stops to ask only when the ask itself is unclear: “clean everything up” asks which workspaces, and a name matching two repositories asks which one. Closing, killing, and removing are not exceptions.
